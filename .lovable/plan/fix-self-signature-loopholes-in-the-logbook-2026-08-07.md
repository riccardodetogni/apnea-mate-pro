# Fix: self-signature loopholes in the logbook

Two related problems, both confirmed in the code and database.

## Problem 1 — an instructor can request a signature from themselves

- `search_instructors` returns every instructor/admin, including the caller, so an instructor searching their own name finds themselves in the "Chiedi la firma" list.
- `request_log_signature` checks ownership of the log and the instructor role of the target, but never that they are different people. A self-request is accepted.
- `sign_requested_log` only checks "is there a pending request addressed to me", so the same person then sees "Firma il libretto richiesto" and signs their own log with just their password — bypassing the autofirma rules.

Currently 0 self-requests exist in the data, so there is nothing to clean up.

### Fix
1. `request_log_signature` rejects the call when the target instructor is the caller (`self_request`).
2. `sign_requested_log` rejects the case where the log owner is also the signer (`self_sign`).
3. `search_instructors` excludes the current user from results, so they never appear as a choice.
4. Friendly Italian message in the modal if those errors ever surface.

## Problem 2 — the yellow "Non verificata / Richiedi firma" banner on the instructor's own register

You are right. When the dive log was generated by a register the instructor themselves manages (creator or listed responsible), asking someone else for a signature makes no sense: they are the credential holder for that outing. Today the page shows the yellow banner with "Richiedi firma" anyway, and offers autofirma only when `outing_type = 'guided'`.

### Fix
- On the dive log detail page, detect whether the current user manages the register that generated this log.
- In that case: no yellow "Richiedi firma" banner. Instead show a neutral "not yet signed" state with the autofirma action as the single, correct next step.
- Autofirma becomes available for the owner-instructor on any log coming from a register they manage, not only `guided` outings. The autofirma flow itself (password re-auth, credential recording) is unchanged.
- For everyone else — a participant whose log comes from someone else's register — the yellow banner and "Richiedi firma" stay exactly as they are.

## Technical notes

- Migration updating three `SECURITY DEFINER` functions:
  - `request_log_signature`: `IF _instructor_user_id = _uid THEN RAISE EXCEPTION 'self_request'`.
  - `sign_requested_log`: raise `self_sign` when the log's `user_id = auth.uid()`.
  - `search_instructors`: add `AND p.user_id <> auth.uid()`.
- Reuse the existing `is_dive_register_manager(_uid, _register_id)` helper, exposed through a small hook that runs when `log.register_id` is set and the viewer is the log owner.
- `src/components/logbook/VerificationBanner.tsx`: accept a `selfManaged` flag; when set and the log is unsigned, render the neutral variant without the request button.
- `src/pages/DiveLogDetail.tsx`: pass the flag, and widen the autofirma condition to `guided || selfManaged`.
- `src/hooks/useSigning.ts` + `src/lib/i18n.ts`: map and localise `self_request` / `self_sign`, plus copy for the neutral banner (IT + EN).
